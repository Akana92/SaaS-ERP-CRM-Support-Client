# Модель и обучающие данные: отдельные пакеты

Код приложения хранится в GitHub. Крупные веса и обучающие данные подготовлены
отдельно для двух **публичных** целевых репозиториев Hugging Face: один типа Model,
второй типа Dataset. Публикация кода не означает запуск сайта или GPU-сервера.
Подготовка пакетов ничего не загружает в интернет и не запускает обучение.

## Что подготовлено

| Пакет | Локальная папка от корня проекта | Размер со служебными файлами |
|---|---|---:|
| Принятый адаптер F | `artifacts/stage8/ml-exports/model` | 148 087 152 байта |
| Только обучающие данные F | `artifacts/stage8/ml-exports/dataset` | 2 649 942 байта |

Веса `adapter_model.safetensors` занимают 132 187 888 байт. Это LoRA-адаптер,
а не полная модель. Пакет модели содержит девять исходных файлов адаптера и
токенизатора, свежую карточку `README.md`, лицензию исходной Qwen
`BASE_MODEL_LICENSE` и `manifest.json`. Полные базовые веса не дублируются.

Базовая модель: `Qwen/Qwen3-4B-Instruct-2507`, точная ревизия
`cdbee75f17c01a7cc42f958dc650907174af0554`. В **копии** `adapter_config.json`
заменён абсолютный путь ноутбука на этот идентификатор и зафиксирована ревизия.
Оригинал в `artifacts/stage5/quality90-v1/training/candidate-f-v13-audited-labels/final_adapter`
не изменён. `manifest.json` содержит SHA-256 и размеры каждого полезного файла,
а у модели также исходные хеши и список двух изменённых полей. Сам манифест
исключён из списка собственных хешей.

Набор данных содержит ровно 13 файлов из `train_sources` конфигурации
`configs/train-quality90-f-v13-audited-labels.json`: 430 диалогов и 1113 целевых
ходов. Внутренний тег этих обучающих записей — `pilot_train`.
Файлы скопированы без изменений с сохранением путей `data/quality90_v1/train/...`.
Это синтетические SaaS/ERP/телеком-ситуации; настоящие данные NLS не заявляются.
Человеческая проверка пока не завершена; AI-аудит охватывал выборку 52 диалога /
155 ходов, а не весь корпус.

## Источники и статус публикации

- Model: [AkanaYB/saas-erp-support-qwen3-4b-adapter-f](https://huggingface.co/AkanaYB/saas-erp-support-qwen3-4b-adapter-f).
- Dataset: [AkanaYB/saas-erp-support-ru-train-v13](https://huggingface.co/datasets/AkanaYB/saas-erp-support-ru-train-v13).

Владелец выбрал публичную видимость. Локальный вход выполнен; upload возвращает
403 из-за токена только для чтения. Успешная загрузка пока не подтверждена.
После загрузки точные commit SHA фиксируются в `configs/asset-sources.json`;
Base уже закреплена, `revision: null` не считается опубликованной версией.
Нельзя загружать целиком `artifacts`, `data` или `models`.

Лицензия Apache-2.0 в `BASE_MODEL_LICENSE` относится к исходным материалам Qwen,
включая токенизатор. Лицензия собственного кода, адаптера и датасета ещё не
выбрана. Публичная доступность не назначает им лицензию Base и сама по себе
не предоставляет коммерческих прав на весь проект.

## Как использовать после скачивания

Для запуска рекомендован [Docker tutorial](DOCKER_TUTORIAL.md); назначение и сценарии описаны в [обзоре проекта](PROJECT_OVERVIEW.md). `scripts/fetch_assets.py` получает только разрешённые файлы по закреплённым commit SHA и проверяет размеры/SHA-256. Для native Windows пути и команды приведены в [PUBLISHING.md](PUBLISHING.md); HF CLI вызывается через `scripts/hf_windows.py` с системным truststore и включённой проверкой HTTPS.

- Базовую модель скачать отдельно в закреплённой ревизии, используя инструкции
  проекта и его закреплённое окружение.
- Адаптер хранить отдельной папкой; приложение должно указывать на неё как на
  PEFT-адаптер к этой базе. Сам адаптер не включает LangGraph, ERP-контекст,
  серверные правила передачи оператору и интерфейс.
- Из Dataset-репозитория восстановить только `data/quality90_v1/train/*.jsonl`
  в корень checkout с сохранением относительных путей; не заменять README проекта
  карточкой датасета. SHA-256 сверить с `manifest.json` и `train_sources`.
  Точные команды загрузки, скачивания и запуска: [PUBLISHING.md](PUBLISHING.md).

Это **не полный пакет воспроизведения эксперимента**. Исходный безопасный запуск
обучения требует отдельного isolation receipt с SHA-256
`1a918393bbc8b1727822d41182b844e3c89451939c7974a862217bc796fa697c`.
Этот защищённый файл не читался и не экспортируется; строка хеша не заменяет
файл. Также не публикуются закрытые вопросы, gold-разметка, сырые оценки,
validation/test, состояния оптимизатора и промежуточные checkpoints.
Без отдельно разрешённого доступа к receipt исходный gate обучения не воспроизводим.

Результат F: 49/100 против Base 10/100 полностью успешных диалогов на
AI-assessed development-проверке NF4 (225 ходов), статус **QUALIFIED**.
Человеческая оценка отсутствует, финальный закрытый test не выполнялся,
`full_success_rate=null`. Это не подтверждённая production-точность.

## Локальная подготовка и проверка

```powershell
.venv/Scripts/python.exe scripts/prepare_ml_exports.py
.venv/Scripts/python.exe -m unittest discover -s tests -p test_ml_exports.py -v
```

Скрипт работает только с точным списком разрешённых файлов, сверяет размеры и
SHA-256, отвергает выход за корень, ссылки/reparse points и перезапись существующего
экспорта. Повторный запуск при уже существующей папке завершится отказом — это
ожидаемая защита от незаметной замены подготовленного пакета.
