# Локальный запуск и передача

Runbook от 19 сентября 2026. Проверенный режим: Windows, Python3.11, RTX3080 Laptop16GB, quality-f/BF16, эффективное внимание sdpa_repeat_kv. Все ERP-данные вымышлены.

## Текущий ноутбук

PowerShell, корень проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/live_demo.py status
Invoke-RestMethod http://127.0.0.1:7860/health
```

Если HTTP доступен и loaded=true, повторный сервер не нужен. Файл status может сохранить старое running после исчезновения процесса, поэтому проверять также health.

Запуск, когда сервер выключен:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/live_demo.py start --adapter-profile quality-f --precision bf16 --attention sdpa_repeat_kv
```

Сначала возвращается dispatched, затем загружаются веса. Готовность: health сообщает loaded=true, adapter_profile=quality-f, client_mode=fine_tuned. [Чат](http://127.0.0.1:7860/client/) и [админка](http://127.0.0.1:7860/admin/) обслуживаются одним FastAPI-сервером; отдельный сервер фронтенда не нужен.

Остановка:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/live_demo.py stop
.\.venv\Scripts\python.exe -X utf8 -B scripts/live_demo.py status
```

stop_requested ещё не означает остановку: завершается текущий запрос. Перед переносом ноутбука дождаться stopped, закрытия HTTP и освобождения GPU. Пауза обучения и выключение live — разные действия. Автозапуск Windows и перезапуск после сбоя пока не настроены.

## Что передавать отдельно

Лёгкий архив содержит код, ERP-фикстуры, политику и отчёты. Сохранить пути относительно распакованного корня:

| Артефакт | Путь | Идентичность |
| --- | --- | --- |
| Основа, tokenizer/config,3 shards,index,лицензия | models/qwen3_4b/ | revision cdbee75f17c01a7cc42f958dc650907174af0554 |
| F: adapter_config.json и adapter_model.safetensors | artifacts/stage5/quality90-v1/training/candidate-f-v13-audited-labels/final_adapter/ | SHA6efc00de7bcecc24872b87de797abd4d9d43ea10e679b23d3b4c13ecb7f7109b |

Основа около8,04GB, адаптер около132MB — размеры файлов, не требование к VRAM. Источник основы закреплён в configs/models.json. Можно передать уже скачанный каталог с LICENSE; не заменять revision. Runtime проверяет SHA адаптера, но не хеширует все shards основы при каждом старте.

Не класть .venv, веса, checkpoints, кэши и журналы в GitHub. Два небольших закреплённых агрегата качества включены в локальный комплект для админки; сами файлы закрытых вопросов не включены. В Git включены только два закреплённых агрегата; остальные runtime/evaluation-артефакты исключены.

## Новое окружение

Нужны Python3.11 и CUDA-совместимый NVIDIA-драйвер. На установку пакетов нужен интернет либо заранее подготовленный отдельный wheel-кэш:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch==2.6.0+cu124 --index-url https://download.pytorch.org/whl/cu124
.\.venv\Scripts\python.exe -m pip install -r requirements-stage2-lock.txt
```

Далее положить отдельные веса в указанные пути и запустить сервис. Lock сохраняет также зависимости прошлых этапов (Gradio/TRL); текущий live UI — HTML/JS и FastAPI. Сокращённый стек не выдаётся за проверенный.

**Чистая установка на другом компьютере ещё не выполнялась.** Проверка распаковки в существующем Python подтверждает комплектность, но не заменяет её. Live задаёт offline-переменные Hugging Face/Transformers и отключает облачный tracing; физическое отключение сети на новом компьютере остаётся отдельной проверкой.

## Проверка перед показом

1. Health подтверждает F, обе страницы открываются.
2. INV-1002: оплата не зарегистрирована в ERP; это не доказательство отсутствия списания в банке.
3. INV-1001: оплаченный пакет и четыре неактивные SIM — обоснованная передача специалисту с историей.
4. BP-2002: инструкция запуска, без заявления о выполнении процесса чатом.
5. Общий вопрос в сравнении: Base без адаптера и F последовательно; показать исходные метки, серверное решение, токены и время.

Закрытый test для показа не нужен. Очередь и действия оператора локальные, подключения к настоящим сотрудникам или ERP NLS нет.

## Если не запускается

- Порт занят: проверить health и процесс, не завершать чужие программы.
- Нет весов/неверный адаптер: сверить пути и SHA; не отключать проверку.
- GPU занят обучением: не обходить общий lock. Обучение проекта завершено и остаётся на паузе.
- Ошибка эффективного ядра на другом стеке: после штатной остановки попробовать start --attention sdpa. Это исходный путь с большей памятью и задержкой на данном ноутбуке.
- Логи находятся в artifacts/stage5/live/<run_id>.stdout.log и .stderr.log. Известное startup-предупреждение subprocess о кодировке встречалось и до оптимизации, источник не установлен. Готовность HTTP проверяется отдельно.

## Сборка

В исходном workspace:

```powershell
.\.venv\Scripts\python.exe -X utf8 -B scripts/build_business_report.py
.\.venv\Scripts\python.exe -X utf8 -B scripts/build_submission.py
```

Первый скрипт считает агрегаты разрешённого ручного smoke, не обучает модель. Второй использует явный список файлов и добавляет manifest. Существующий архив не перезаписывается: повторную сборку делать с новым --output.

Первый локальный архив является историческим снимком. Текущая GitHub-поставка содержит код и презентацию; Hugging Face-артефакты подготавливаются отдельно. Актуальная инструкция: [PUBLISHING.md](PUBLISHING.md). Лицензия собственного кода, адаптера и корпуса ещё не выбрана. Apache-2.0 у основы не определяет права на весь продукт. Полное повторение обучения из демо-архива не заявляется: конфигурация и [карточка F](DATASET_FINAL_F.md) указывают на отдельные train-артефакты. Для полного исследования нужен исходный workspace и разрешённые отдельные данные.
