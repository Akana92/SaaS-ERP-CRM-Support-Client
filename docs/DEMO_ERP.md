# Демо-ERP: счета, SIM и доступы

Демо связывает обращения с вымышленными объектами ERP. Сервер читает их состояние, передаёт разрешённые факты модели и применяет правила передачи оператору. Чат не оплачивает счета, не активирует SIM, не выдаёт права и не запускает бизнес-процессы.

## Как проверить

1. Откройте [клиентский чат](http://127.0.0.1:7860/client/), выберите «Клиент» или «Сотрудник».
2. Раскройте «Примеры для демо-ERP». Выбор примера подставляет вопрос; отправьте его самостоятельно. При заполненном черновике интерфейс защищает его от замены.
3. После ответа задайте уточнение в той же беседе. Номер объекта можно не повторять: сервер ищет последнюю ссылку в сообщениях пользователя.
4. Для другой темы создайте новое обращение. В [админке](http://127.0.0.1:7860/admin/) откройте обращение и шаг `erp_lookup`: он показывает, найден ли разрешённый объект. Переданные обращения доступны в очереди оператора вместе с перепиской.

В «Сравнении моделей» доступны те же примеры для выбранной роли. Один вопрос получают Base и Fine-tuned; последующие ходы продолжают отдельную историю каждой модели. Сравнение показывает решение о передаче, но не создаёт настоящую карточку очереди.

## Учебные объекты

| Роль | Номер | Факты и ожидаемое поведение |
| --- | --- | --- |
| Клиент | `INV-1001` | Оплата подтверждена; из шести SIM две активны, четыре ожидают активации. Причина неизвестна; сервер требует проверки оператором. |
| Клиент | `INV-1002` | Оплата не зарегистрирована в учебной ERP. Это не доказывает отсутствие списания в банке; нельзя автоматически предлагать повторную оплату. |
| Клиент | `SIM-1001` | Комплект из шести SIM: две активны, четыре ожидают активации; оплата подтверждена. Причина и срок активации неизвестны; требуется оператор. |
| Сотрудник | `BP-2001` | Роль «Наблюдатель» не позволяет запускать подключение. Проверку доступа выполняет демо-группа управления доступом через очередь. |
| Сотрудник | `BP-2002` | Роль «Менеджер подключений» позволяет запуск. Доступна инструкция: «Клиенты → Заявки → Новое подключение». Чат объясняет шаги, но не выполняет их. |

Источник фактов — [live-objects.json](../data/erp/live-objects.json); правила выбора объекта — [live_erp.py](../src/support/live_erp.py). Эти данные не описывают реальные системы или клиентов NLS.

## Границы демо

- Нужен точный номер вида `INV-1001`, `SIM-1001` или `BP-2001`. Регистр букв не важен. Без номера доступна общая справка либо последний объект беседы; несколько разных номеров в одном сообщении не объединяются.
- Новый вопрос без номера может продолжить старый объект. Автоматическое надёжное определение смены темы пока не реализовано.
- У каждой роли один общий вымышленный пользователь. Проверка организации, роли и владельца объекта демонстрирует изоляцию фактов, но не заменяет авторизацию реальных пользователей.
- Неизвестный или недоступный объект не раскрывает свои факты. При этом модель может завершить обработку резервной передачей оператору.
- Серверные правила обязательной передачи могут повторять одно объяснение на уточняющих вопросах. Сырой ответ модели и итоговое решение сервера нужно различать в разборе.
- Скорость ещё требует доработки: в пяти клиентских вызовах ответ занимал около 32–67 секунд. Проверенное сравнение завершилось после лимита ожидания проверочного скрипта в 240 секунд: Base — 99,785 секунды, Fine-tuned — 334,082 секунды. Повторно запрос не отправлялся. Это замеры конкретного прогона, а не гарантия времени ответа; приемлемая скорость пока не подтверждена.
- Исправлен обнаруженный пропуск случайных латинских букв фильтром ввода. На работающем сервере проверено: два предупреждения, после третьего некорректного сообщения — блокировка на пять минут. Эти попытки не вызывают модель и не создают обращения оператору. Это проверка конкретных примеров, а не гарантия распознавания любого бессмысленного текста.

Работает закреплённый кандидат F в BF16. Прежние 49/100 против 10/100 относятся к отдельной оценке NF4, имеют статус QUALIFIED и не являются оценкой качества этого демо или подтверждением человеком. Новое обучение и итоговый закрытый test для этой функции не запускались.

Запуск, проверка статуса и остановка перед переносом ноутбука описаны в [руководстве локального сервера](LOCAL_RUN_AND_DELIVERY.md). Результаты проверки функции — приёмка демо-ERP (исторический протокол хранится локально).
